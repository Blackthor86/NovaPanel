# راه‌اندازی NovaPanel

NovaPanel یک برنامهٔ Node.js است که پنل وب و مسیر‌دهی اتصال‌ها را روی **یک پورت عمومی** اجرا می‌کند. برای نصب جداگانهٔ Python یا سرویس دوم نیازی نیست.

## استقرار روی هاست

1. در GitHub Actions مخزن، اجرای موفق CI را باز کن و Artifact به نام \`NovaPanel-node-deploy\` را دانلود کن. در اجرای Pull Request نام Artifact برابر \`NovaPanel-standalone-preview\` خواهد بود.
2. Artifact دانلودشده یک ZIP بیرونی است که فایل \`NovaPanel-standalone.zip\` داخلش قرار دارد. ابتدا ZIP بیرونی را استخراج کن و سپس ZIP داخلی را هم استخراج کن؛ فایل \`package.json\` باید مستقیماً در ریشهٔ پوشهٔ برنامه باشد.
3. Runtime را روی Node.js 22 قرار بده و دستور شروع را \`npm start\` بگذار.
4. اگر هاست متغیر \`SERVER_PORT\` را خودش تنظیم می‌کند، آن را تغییر نده. برنامه این متغیر را به \`PORT\` ترجیح می‌دهد.
5. برای \`NOVAPANEL_DATA_DIR\` یک مسیر قابل‌نوشتن روی ذخیره‌سازی پایدار انتخاب کن تا رمز، UUID، توکن اشتراک، مسیرها و گواهی بعد از restart عوض نشوند.
6. مطمئن شو نصب خودکار Xray فعال است (پیش‌فرض \`NOVAPANEL_AUTO_INSTALL_XRAY=1\`). پنل می‌تواند هنگام دریافت و شروع موتور آنلاین شود؛ قبل از تست اتصال صبر کن تا وضعیت موتور «فعال» شود.
7. دامنهٔ عمومی وب را باز کن. بار اول یک رمز مدیر انتخاب کن. سپس لینک **Subscription** را کپی کن، در بخش Subscription کلاینت V2Ray وارد کن و Update/Refresh را بزن. لینک تکی \`vless://\` جایگزین لینک اشتراک نیست.

## مسیرهای خروجی

توکن داخل لینک اشتراک باید محرمانه بماند.

| مسیر | خروجی |
|---|---|
| \`/knight/sub?token=…\` | اشتراک Base64 مناسب کلاینت‌های V2Ray |
| \`/knight/raw?token=…\` | فهرست متن سادهٔ لینک‌ها |
| \`/knight/clash?token=…\` | فایل YAML برای Clash |
| \`/knight/sb?token=…\` | JSON برای sing-box |
| \`/knight/xray?token=…\` | JSON برای Xray |

لینک اشتراک اصلی در داشبورد نمایش داده می‌شود؛ لازم نیست token را دستی بسازی.

## تنظیم حالت اتصال

در حالت \`direct\` پیش‌فرض، هاست باید خودِ پورت TCP اختصاص‌داده‌شده را به برنامه برساند. این حالت برای WS، HTTPUpgrade، gRPC، XHTTP، Shadowsocks و Reality روی هستهٔ Xray کانفیگ می‌سازد. گواهی TLS در این حالت خودامضا است و لینک‌ها fingerprint/pin لازم را دارند.

فقط اگر هاست HTTPS را در لبه خاتمه می‌دهد و WebSocket Upgrade را تا برنامه منتقل می‌کند، حالت \`NOVAPANEL_LINK_MODE=edge\` را انتخاب کن. در حالت edge نمی‌توان از Reality یا gRPC خام استفاده کرد.

## بررسی واقعی

- مسیر \`/api/health\` باید JSON و پورت گوش‌دادن برنامه را نشان دهد.
- داشبورد باید وضعیت موتور را \`running\` گزارش کند.
- سپس اشتراک را در کلاینت وارد و به‌روزرسانی کن و اتصال واقعی را تست کن. بازشدن داشبورد یا تولیدشدن لینک به‌تنهایی اثبات اتصال نیست.

تست‌ها را محلی با \`npm test\` اجرا کن. CI هر ۱۳ پروفایل تولیدشده را با کلاینت واقعی Xray تا یک سرویس مقصد کنترل‌شده بررسی می‌کند؛ Reality هم مستقیم به ورودی داخلی و هم از مسیر پورت عمومی تست می‌شود. این تست‌ها روی runner گیت‌هاب اجرا می‌شوند؛ بنابراین دسترسی شبکه، پورت TCP خام و reverse proxy در Botkeep یا هر میزبان دیگر باید بعد از استقرار روی خود همان میزبان هم آزمایش شود. پیش‌فرض Reality اکنون \`www.cloudflare.com\` است تا با محدودیت اندازهٔ گواهی در بعضی نسخه‌های Xray برخورد نکند. مقصد سفارشی را فقط پس از تست TLS 1.3 و HTTP/2 تنظیم کن.

## امنیت

پوشهٔ داده را پاک نکن و آن را عمومی نکن. لینک اشتراک دربرگیرندهٔ توکن است. رمز مدیر، توکن اشتراک و کلید خصوصی TLS را منتشر نکن. پیش از انتشار عمومی [SECURITY.md](../SECURITY.md) را بخوان.
